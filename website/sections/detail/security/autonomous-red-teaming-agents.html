9Engineering Breakdown
  • Reconnaissance and attack-surface mapping — builds a picture of what is exposed before anything is attacked. Key parts: network and port scanners, service and version fingerprinting, web crawlers and API discovery, cloud and identity enumeration, open-source intelligence collection.
  • Planner and orchestrator — the reasoning loop that decides what to try next and keeps track of what has been learned. Key parts: large language model planner with tool calling, tool registry, memory store of findings and failed attempts, budget and step limits.
  • Exploit engine — turns a suspected weakness into a working, repeatable attack. Key parts: automated payload generation, fuzzers, debuggers and dynamic analysis, exploit chaining across hosts and accounts.
  • Sandbox and target replica — a disposable copy of the target where attacks can be run without harming anything real. Key parts: isolated virtual machines or containers, blocked outbound network access, snapshot and rollback, cloned credentials and configuration.
  • Verification and reporting — separates genuine exploitable flaws from plausible-looking noise. Key parts: clean-snapshot replay, false-positive filtering and de-duplication, severity scoring, fix recommendations and evidence logs.
  • Guardrails and authorisation — keeps an autonomous attacker inside the agreed scope. Key parts: scope allow-lists, rate limiting, full action logging, kill switch and human approval gates.
10How It Would Be Made — Step by Step
  1. Agree scope and authorisation. Write rules of engagement naming exactly which hosts, accounts and time windows may be touched, and which techniques are forbidden — without this, none of the rest is legal.
  2. Clone the target environment. Stand up an isolated replica: the same services, versions and configurations, with no route to production or the public internet, and snapshotting so any state can be rewound in seconds.
  3. Expose tools as callable actions. Install scanners, fuzzers, debuggers and exploitation frameworks inside the sandbox and wrap each one in a structured interface with typed arguments and parsed output.
  4. Wire the agent loop. Connect an LLM to that tool interface with a plan–act–observe cycle: propose an action, run it, read the result, update the findings graph, decide again.
  5. Ground it in vulnerability knowledge. Add retrieval over vulnerability databases, patch notes and public write-ups so generated payloads match real product versions instead of being invented.
  6. Map the attack surface. Let the agent enumerate hosts, services, endpoints and exposed credentials, and assemble them into a graph of reachable paths.
  7. Attempt and chain exploits. The agent generates candidate payloads, tests them in the replica, keeps what works and combines single weaknesses into multi-step chains leading to a high-value target.
  8. Verify on a clean snapshot. Replay every claimed exploit from a fresh copy. Anything that cannot be reproduced is discarded, which removes most hallucinated findings.
  9. Report and hand back to humans. Produce findings with reproduction steps, evidence, severity and remediation advice, and route anything touching live systems to a human for approval before it is attempted.
11Prerequisite Technologies
  • EXISTS Large language models with reliable tool use — the agent must choose tools, parse messy output and hold a long multi-step plan without losing the thread.
  • EXISTS Cheap, disposable sandboxing — running unknown exploits safely requires isolation and instant rollback, which virtual machines and containers already provide.
  • EXISTS Mature scanning and exploitation tooling — established scanners, fuzzers and exploitation frameworks do the mechanical work the agent orchestrates.
  • PARTIAL Evaluation benchmarks for offensive agents — without standard scored challenges it is hard to tell a capable agent from one that writes convincing but false reports.
  • PARTIAL Reliable scope enforcement — an agent that misreads its scope can cause real damage; allow-lists and kill switches are improving but not foolproof.
12Path to Full Scale
  1. Now: LLM assistants that speed up human penetration testers and automate reconnaissance plus known-vulnerability checks — cheaper, more frequent security audits for organisations that could never afford constant manual testing.
  2. Next: agents that autonomously chain multi-stage exploits inside sandboxed replicas and prove each one by replay, as pushed by DARPA's AI Cyber Challenge — verified, reproducible findings at machine speed with humans reviewing rather than hunting.
  3. Next: continuous red-teaming wired into software delivery pipelines, running under strict scope against staging environments — vulnerabilities found and fixed before release instead of after a breach.
  4. Longer term: paired attack-and-defence agents that find and patch in the same loop, under audited guardrails and clear liability rules — a security posture that improves faster than attackers can exploit it — provided the same capability is not turned loose without oversight.
