9Engineering Breakdown
  • Environment model — represents the target network: hosts, services, vulnerabilities and connections. Key parts: topology graph, vulnerability and configuration database, reachability and trust relationships.
  • Agent or planner — decides the next action — scan, exploit, pivot, escalate — to reach a goal. Key parts: policy network (reinforcement learning) or language model, action space definition, reward or objective function.
  • Action execution layer — carries out chosen actions using real security tools. Key parts: scanners (e.g. Nmap), exploitation frameworks (e.g. Metasploit), remote access and lateral movement tools.
  • Observation and state updater — collects results from actions and updates the environment model. Key parts: log and session parsers, graph update logic, uncertainty tracking.
  • Safe execution sandbox — keeps the agent contained so it cannot damage real systems. Key parts: isolated virtual network, snapshot and rollback, scope enforcement and kill switch.
  • Reporting and remediation — turns discovered attack paths into findings for defenders. Key parts: attack graph visualisation, severity scoring (e.g. CVSS), patch and hardening recommendations.
10How It Would Be Made — Step by Step
  1. Build a target environment. Create a realistic network — either a digital twin of the real one or a cyber range — with hosts, services, users and known weaknesses.
  2. Define the agent interface. Specify the observation space (what the agent sees) and action space (what it can try), using tactics from frameworks such as MITRE ATT&CK.
  3. Generate or collect experience. Run human red-team playbooks, scripted attacks, or millions of simulated episodes to give the agent examples of successful and failed paths.
  4. Train the decision maker. Use reinforcement learning with rewards for reaching goals and penalties for noise, or fine-tune a language model to reason over tool outputs and pick actions.
  5. Validate against a baseline. Compare the agent's findings, speed and false-positive rate with a human red team on the same range.
  6. Connect to real tools under guardrails. Integrate scanners and exploitation frameworks, but enforce scope limits, human approval for risky actions, and full logging.
  7. Deploy for continuous testing. Run the agent on a schedule against production-like environments, feeding results to defenders and retraining as the network changes.
11Prerequisite Technologies
  • EXISTS Reinforcement learning and planning algorithms — they let an agent learn sequences of actions toward a distant goal.
  • EXISTS Mature offensive security tooling with APIs — scanners, exploitation frameworks and remote access tools are the agent's hands.
  • PARTIAL Realistic network simulation and cyber ranges — training and safe testing require environments that behave like real enterprise networks.
  • PARTIAL Large language models for tool use — they help interpret unstructured outputs and plan, but can hallucinate or take unsafe actions.
  • PARTIAL Containment and safety controls — an autonomous attacker must be impossible to leak beyond its authorised scope.
12Path to Full Scale
  1. Now: automated scanners and scripted exploitation in lab environments — faster, repeatable discovery of known vulnerabilities.
  2. Next: agents that chain multiple exploits and move laterally in cyber ranges — testing of defence-in-depth against realistic multi-step attacks.
  3. Next: hybrid teams where a human red-teamer directs several AI agents — scaled continuous testing without losing human judgement.
  4. Longer term: fully autonomous red teaming inside strict guardrails — round-the-clock adversarial testing of live networks — if safety and control problems are solved.
