9Engineering Breakdown
  • Post-quantum signature scheme — authenticates transactions so they cannot be forged by a quantum computer. Key parts: lattice-based signatures (e.g. ML-DSA), hash-based signatures (e.g. SLH-DSA, XMSS), key generation, signing and verification routines.
  • Ledger protocol — defines how transactions and blocks are structured and validated. Key parts: transaction serialization, block validation rules, consensus mechanism.
  • Key management — generates, stores and uses the much larger private keys safely. Key parts: wallet software, hardware security modules, key derivation and backup.
  • Network layer — propagates transactions and blocks between nodes. Key parts: peer-to-peer protocol, mempool, block and transaction relay.
  • Migration and interoperability — lets a ledger move from classical to post-quantum cryptography without splitting the network. Key parts: hybrid signature verification, dual-format addresses, cross-chain bridges.
  • Cryptographic agility — allows algorithms to be swapped if weaknesses are later found. Key parts: algorithm identifiers, versioning, upgrade and activation mechanisms.
10How It Would Be Made — Step by Step
  1. Select algorithms. Choose standardised post-quantum signature schemes (for example ML-DSA or SLH-DSA) based on security level, key and signature size, and verification speed.
  2. Design the transaction format. Extend the transaction structure to carry public keys and signatures that are kilobytes in size, versus tens of bytes for elliptic-curve signatures.
  3. Implement verification. Rewrite node software to verify the new signatures, optimising code so validation does not slow block processing too much.
  4. Integrate with consensus. Modify block validation rules to accept the new signature types, while keeping the chain consistent for nodes that have not yet upgraded.
  5. Rework addresses. Derive addresses from the new public keys, typically by hashing, so users keep short, collision-resistant identifiers.
  6. Update wallets. Add key generation, secure storage and signing for the larger keys into desktop, mobile and hardware wallets.
  7. Plan the migration. Run a hybrid mode where transactions must carry both a classical and a post-quantum signature, then schedule a cut-over height.
  8. Test and audit. Operate testnets, commission independent security audits, and benchmark throughput under realistic load.
  9. Activate on the network. Coordinate a software upgrade across miners, validators, exchanges and node operators, then monitor for forks or failures.
11Prerequisite Technologies
  • EXISTS Standardised post-quantum algorithms — NIST finalised its first post-quantum standards in 2024, giving ledgers proven algorithms to build on.
  • PARTIAL Efficient hardware for post-quantum cryptography — post-quantum operations are slower and produce larger data, so hardware acceleration and bigger blocks may be needed.
  • PARTIAL Secure storage for larger keys — hardware wallets and secure enclaves have limited space and must be updated to hold multi-kilobyte keys.
  • PARTIAL Cryptographic agility in existing ledgers — most ledgers hard-code their signature scheme, so adding a new one requires a carefully managed protocol change.
  • PARTIAL Consensus that tolerates larger transactions — bigger signatures reduce the number of transactions per block, which may require layer-2 solutions or parameter changes.
12Path to Full Scale
  1. Now: NIST post-quantum standards published; niche ledgers such as the Quantum Resistant Ledger already use hash-based signatures like XMSS — real, audited building blocks for quantum-resistant systems.
  2. Next: major ledgers deploy hybrid classical-plus-post-quantum signatures on testnets and then mainnet — protection against quantum attack without forcing every user to switch at once.
  3. Next: full post-quantum migration for wallets, exchanges and smart contracts — a ledger where no part of the transaction flow relies on breakable cryptography.
  4. Longer term: quantum-resistant consensus and cross-chain communication, possibly with quantum key distribution for high-value links — end-to-end security even if large-scale quantum computers arrive.
