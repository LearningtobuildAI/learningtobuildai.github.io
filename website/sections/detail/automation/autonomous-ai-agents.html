PART 3Engineering & Build Guide
Available today

Written by DeepSeek (deepseek-flash) on 29 Sep 2026. General engineering knowledge, not a manufacturer's procedure.

9Engineering Breakdown
  • Model backbone — the language model that reads context and decides the next action. Key parts: transformer neural network, context window, optional fine-tuning or preference tuning.
  • Control loop — repeatedly plans, acts and observes until the task is done. Key parts: planner / task decomposition, reason-and-act prompting loop, stop and retry logic.
  • Tool layer — lets the agent actually change things outside the model. Key parts: tool-calling or function-calling API, sandboxed code execution, browser and file access, connectors to business systems.
  • Memory and retrieval — stores what happened and fetches relevant knowledge. Key parts: vector database with embeddings, summarisation of past turns, structured scratchpad or state store.
  • Guardrails and permissions — bounds what the agent may do without a human. Key parts: allow-lists and scoped credentials, human approval checkpoints, input/output filters.
  • Evaluation and observability — measures whether runs succeed and why they fail. Key parts: task benchmarks, trajectory logging and tracing, cost and latency meters.
10How It's Made — Step by Step
  1. Choose and test the base model. Pick a model whose context window, tool-calling ability and cost fit the job; benchmark it on the real tasks, not generic chat tests.
  2. Define the tools. Write a small, well-documented set of callable functions — search, read file, send message, query database — each with typed inputs and outputs, since vague tool descriptions are a main cause of wrong actions.
  3. Write the loop and prompt. Specify the system prompt, the reason-act-observe cycle, and the rules for when to stop, retry or ask a human.
  4. Add memory. Embed past interactions and documents into a vector store so the agent can retrieve relevant facts instead of relying on the whole history fitting in context.
  5. Sandbox execution. Run generated code and network calls in an isolated environment with narrowly scoped credentials, so a mistake cannot delete production data or leak secrets.
  6. Build the evaluation harness. Create a test set of representative tasks with pass/fail checks, then run every prompt or model change against it to catch regressions.
  7. Deploy with human checkpoints. Start in a supervised mode where irreversible actions need approval, log every step, and widen autonomy only as measured success rates justify it.
11Prerequisite Technologies
  • EXISTS Large language models with tool use — the reasoning and structured output that an action loop depends on.
  • EXISTS Retrieval-augmented generation — supplies task-relevant knowledge beyond what the model memorised.
  • EXISTS Vector databases and embeddings — the usual way to store and search long-term memory cheaply.
  • PARTIAL Reliable long-horizon planning — error rates compound over many steps, so agents drift or loop on tasks that take dozens of actions.
  • PARTIAL Robust evaluation and sandboxing — without it, autonomy is unsafe and improvements cannot be measured.
12Where It Goes Next
  1. Now: single-domain agents that draft, code, search and file tickets under supervision — real time savings on bounded, reversible tasks.
  2. Next: standard tool and permission protocols so agents can cross between systems — agents that finish a workflow end to end instead of one step.
  3. Next: verifiable planning, where the agent checks its own intermediate results — longer, less supervised runs with fewer compounding errors.
  4. Longer term: organisations running many cooperating agents with audited permissions — autonomous business processes — contingent on solving reliability, security and accountability.

18Glossary
ReAct prompting loops
A method for generating actions based on a task description, using a loop of feedback to refine the agent's understanding and actions.
LLM (Large Language Model)
A type of AI model trained on large datasets that can generate human-like text and perform various language-related tasks.
Tool-use APIs
Application Programming Interfaces allowing the autonomous agent to interact with external tools and services.
