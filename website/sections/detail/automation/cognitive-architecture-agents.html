9Engineering Breakdown
  • Foundation model — core reasoning engine: understands instructions, generates plans and text. Key parts: transformer neural network, pretrained weights, context window.
  • Planner — breaks a high-level goal into ordered, actionable steps. Key parts: task decomposer, dependency graph, replanner for failures.
  • Memory — retains project state, past actions and learned facts across long tasks. Key parts: short-term context buffer, vector database for long-term recall, summariser to compress history.
  • Tool interface — lets the agent act beyond text — call APIs, run code, search the web. Key parts: function-calling schema, API connectors, sandboxed code runtime.
  • Verifier — checks each output against goals or tests and triggers correction. Key parts: unit tests and schema validators, critic model, human-in-the-loop checkpoints.
  • Orchestrator — runs the plan-act-observe-verify loop and manages state. Key parts: control loop, state machine, logging and audit trail.
10How It Would Be Made — Step by Step
  1. Select or train the foundation model. Choose a large language model with strong reasoning and instruction-following, or fine-tune one on examples of multi-step tasks.
  2. Define the tool set. List every external action the agent may take — reading files, calling APIs, running code — with strict input/output schemas.
  3. Build the memory system. Set up a vector database to store and retrieve past steps and facts; add summarisation to keep the active context within the model's window.
  4. Implement planning. Prompt the model to decompose goals into steps, or train a separate planner; represent steps as a dependency graph so order can adapt.
  5. Create the execution loop. Code the cycle: plan, act via tools, observe results, verify, then revise or continue. Add retries and hard limits to prevent runaway loops.
  6. Add verification layers. For code, run unit tests; for data, validate schemas; for open-ended work, use a second model as critic or require human approval at key checkpoints.
  7. Evaluate on multi-step benchmarks. Assemble realistic project tasks, measure success rate, cost, and failure modes, then iterate on prompts, memory design and tool reliability.
  8. Deploy with guardrails. Run tools in sandboxes with least-privilege permissions, rate-limit actions, log every step, and keep rollback and human override available.
11Prerequisite Technologies
  • EXISTS Large language models with strong reasoning — they provide the core ability to understand instructions and generate plausible plans.
  • EXISTS Tool and function-calling APIs — they let the model invoke external actions in a structured, reliable way.
  • EXISTS Vector databases and retrieval — they enable memory beyond the model's context window.
  • EXISTS Sandboxed execution environments — they safely contain generated code and other risky actions.
  • PARTIAL Automated verification for open-ended tasks — unit tests work for code, but checking a legal brief or a marketing plan is much harder.
  • PARTIAL Reliable long-horizon planning — current models still drift, repeat steps or lose the goal over many actions.
12Path to Full Scale
  1. Now: single-task agents (coding assistants, customer-service bots) that handle narrow, well-defined jobs with human oversight — productivity gains in bounded tasks.
  2. Next: multi-step agents that complete projects in domains with clear success criteria, such as coding and data analysis, with minimal supervision — automation of routine professional workflows.
  3. Next: agents that manage ambiguous knowledge work using learned verification and memory, with human review at checkpoints — assistance on complex, open-ended projects.
  4. Longer term: teams of specialised agents that collaborate on large projects with robust verification and safety guarantees — scalable autonomous knowledge work.
