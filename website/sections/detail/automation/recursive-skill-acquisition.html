9Engineering Breakdown
  • Gap detector — recognises that the current task cannot be completed with the skills already available. Key parts: failure classifier reading stack traces and test output, self-critique prompt over the failed attempt, task-feasibility estimate.
  • Skill synthesiser — writes the missing capability as executable code or a documented procedure. Key parts: code-generating language model, API and documentation lookup, parameter and interface specification.
  • Sandboxed runtime — executes the new script safely, with no way to damage real systems. Key parts: container or virtual machine, interpreter and package manager, file system snapshot and network allowlist.
  • Verifier — decides whether the new skill actually works before it is trusted or remembered. Key parts: unit tests and assertions, execution outcome and reward signal, model-based critic.
  • Skill library — stores verified skills as reusable, described functions rather than one-off transcripts. Key parts: vector index over skill descriptions, versioning and dependency metadata, composition rules for chaining skills.
  • Orchestrator — runs the propose–attempt–learn loop and decides what to try next. Key parts: task decomposition and planning, curriculum generator, stop conditions and budget limits.
10How It Would Be Made — Step by Step
  1. Choose a verifiable environment. Pick a domain where success or failure is unambiguous — a simulated back-office system, a code repository with a test suite, or a game with a score. Without a cheap automatic check, the loop cannot close.
  2. Instrument execution. Give the agent a sandboxed container with an interpreter, a package manager, a scratch file system and controlled access to the target APIs, plus full logging of every action.
  3. Run the basic loop. The agent is given a task, proposes a plan, writes code, runs it, and reads back the output and any error. This alone is ordinary tool use, not learning.
  4. Add failure attribution. When a run fails, the system classifies why — wrong API, wrong argument, missing permission, bad logic — so the next attempt changes the right thing rather than retrying blindly.
  5. Curate before committing to memory. Only skills that pass their tests are saved, deduplicated against existing entries, and rewritten as a documented function with an explicit signature. Junk in the library poisons later retrieval.
  6. Build retrieval and composition. Index the library by description so the planner can pull in the right skill and chain two or three together to solve a task none of them solves alone.
  7. Generate the next task. The curriculum generator proposes a task just beyond the agent's current reach, based on which skills exist and which attempts recently failed.
  8. Add regression and safety gates. Re-run older task suites after every library change to catch skills that overwrite or break earlier ones, and cap what the agent may do to real systems without human approval.
11Prerequisite Technologies
  • EXISTS Large language models that write reliable code — the synthesised skill is usually a script, so code quality sets the ceiling on everything else.
  • EXISTS Cheap sandboxed execution and tool APIs — the loop needs thousands of attempts, which must be safe and nearly free.
  • PARTIAL Automated verification of success — tests and scores exist for code and games but not for most white-collar tasks, which is the central bottleneck.
  • PARTIAL Long-term memory and retrieval — a library is only useful if the right skill is found at the right moment without degrading over time.
  • PARTIAL Oversight and permission controls — an agent that writes and runs its own procedures can also automate its own mistakes.
12Path to Full Scale
  1. Now: research agents that build and reuse skill libraries inside games and software benchmarks — proof that the loop can raise success rates without humans writing each new capability.
  2. Next: closed-domain assistants that propose new skills with human review before they are committed — use in document processing, data entry and IT operations where output is checkable.
  3. Next: self-curated libraries with continuous regression testing — agents that keep improving on long-running workflows without drifting into error.
  4. Longer term: transfer of skills between domains and agents — capability growth that compounds across an organisation, but also makes oversight and auditability the binding constraint.
