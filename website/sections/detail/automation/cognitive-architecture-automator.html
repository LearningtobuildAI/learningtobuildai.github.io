Written by DeepSeek (deepseek-flash) on 29 Sep 2026. General engineering knowledge, not a manufacturer's procedure. Steps for anything not yet built are a theoretical route, not a plan anyone is executing.

9Engineering Breakdown
  • Observation layer — gathers the digital traces of work without interrupting it. Key parts: endpoint agents (window focus, app switches, screen frames), SaaS API and webhook taps (tickets, chats, documents, code), central event bus with timestamps and user IDs.
  • Identity and permission mapping — makes sure a reconstructed page is only visible to people who could see the source material. Key parts: directory/SSO sync, role and team graph, permission inheritance rules.
  • Workflow reconstruction — turns a messy event stream into repeatable procedures. Key parts: sessionisation and deduplication, process-mining / sequence modelling, variant clustering across people and teams.
  • Knowledge synthesis — writes and updates the wiki text itself. Key parts: long-context language model, entity and step extraction, retrieval-augmented generation over a vector index and knowledge graph, citation linker back to source events.
  • Governance and privacy — keeps observation lawful, bounded and auditable. Key parts: PII and secret detection/redaction, consent and scope registry, retention and deletion jobs, access and audit logs.
  • Curation interface — puts a human between machine drafts and the published page. Key parts: review queue and diff viewer, approve/reject and edit capture, drift and staleness alerts.
10How It Would Be Made — Step by Step
  1. Connect the sources. Wire the enterprise directory, chat, ticketing, document and version-control systems into a single event stream, plus an endpoint agent for activity that never reaches a server.
  2. Set consent, scope and redaction. Each team opts in per tool and per data type; rules strip personal data, credentials and anything outside the agreed scope before storage.
  3. Capture low-level events. Record app focus changes, document and ticket IDs, command invocations and clipped screen regions, all time-stamped. Content is captured only where consent allows.
  4. Sessionise and correlate. Group events into work sessions, then apply process-mining techniques to recover the order of steps and the tools involved.
  5. Find stable procedures. Keep sequences that recur across people and weeks; discard one-off or low-confidence paths. Score each candidate with a confidence value.
  6. Draft articles. A long-context model writes a step-by-step page from the winning sequence, grounding every claim in retrieved source events and emitting links to them.
  7. Diff against the live wiki. Compare the draft with existing pages to detect stale steps, contradictions and gaps; propose edits rather than blind overwrites.
  8. Review, publish, version. A domain expert edits and approves; the change is committed with authorship, provenance and a rollback path.
  9. Watch for drift. Monitor the event stream for divergence from the published procedure and regenerate drafts, lowering confidence where evidence thins.
11Prerequisite Technologies
  • EXISTS Long-context language models — summarising hours of interleaved events into readable steps needs very large context windows.
  • EXISTS Retrieval-augmented generation and vector search — keeps generated text anchored to real source records instead of plausible invention.
  • EXISTS Process mining and event-log analysis — supplies the statistical backbone for inferring ordered workflows from raw logs.
  • PARTIAL Permission-aware retrieval — a wiki page built from several systems must inherit the strictest source permission, which few pipelines enforce today.
  • PARTIAL Scalable on-device or private redaction — detecting personal data before it leaves the endpoint is the difference between a useful tool and a compliance breach.
12Path to Full Scale
  1. Now: assistants that draft pages from tickets, meeting notes and repositories — faster onboarding and less manual documentation.
  2. Next: per-team workflow capture with human review before every publish — runbooks that track the real process rather than the intended one.
  3. Next: cross-tool process graphs with inherited permissions and provenance — living documentation that doubles as audit evidence.
  4. Longer term: knowledge bases that flag process friction, not just describe it — feedback from the record of work into how work is designed.
