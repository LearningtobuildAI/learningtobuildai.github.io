9Engineering Breakdown
  • Data ingestion and normalisation — pulls market prices, filings and reference data into one clean, queryable store. Key parts: market-data feed adapters, regulatory filing parsers (XBRL and PDF), corporate-action and FX adjusters, point-in-time time-series database.
  • Quantitative modelling engine — computes valuation, risk and screening metrics from the clean data. Key parts: discounted-cash-flow and comparable-company models, factor and risk models, scenario and sensitivity engine, backtesting harness.
  • Language-model reasoning layer — turns numbers and retrieved documents into readable analysis. Key parts: document chunker and vector index, prompt and tool-use orchestration, citation enforcement, model fallback chain.
  • Orchestration and scheduling — runs the pipeline automatically when new data lands. Key parts: workflow engine, job queue, event triggers such as earnings releases, run versioning and replay.
  • Verification and guardrails — catches arithmetic, grounding and consistency errors before a human reads the output. Key parts: deterministic recalculation checks, numeric-consistency tests, source-citation validator, audit log.
  • Delivery and workflow integration — puts the finished output where analysts actually work. Key parts: document and slide rendering, internal API, desktop and terminal integration, access control.
10How It Would Be Made — Step by Step
  1. Define the analytical scope. Fix which statements, metrics and model templates are in scope — a narrow, well-specified mandate is far easier to automate than open-ended research.
  2. Build the data pipeline. Connect to market-data and filing sources, standardise units and currencies, and store everything point-in-time so backtests cannot accidentally use data that was not yet published.
  3. Encode the models as deterministic code. Write the valuation and ratio maths as ordinary tested software rather than asking a language model to do arithmetic, and reconcile it against independently built spreadsheets.
  4. Add retrieval and language generation. Index filings, transcripts and prior notes so the model can quote them; give it tools that call the modelling engine so every figure comes from code, not from the model's memory.
  5. Enforce grounding and traceability. Require each number and claim to carry a source pointer, and configure the system to omit an item and flag it rather than guess when data is missing.
  6. Build an evaluation harness. Assemble a fixed set of analyst-written memos and filings with known answers, then measure numeric accuracy, citation correctness and error rate on every model or prompt change.
  7. Insert human review gates. Route drafts to an analyst for approval, log edits, and feed those corrections back into the evaluation set.
  8. Deploy with monitoring. Watch for broken feeds, data drift and silent model updates; pin model versions and re-benchmark on a schedule.
11Prerequisite Technologies
  • EXISTS Machine-readable market and filing data — structured filings and vendor price feeds are the raw material; without them nothing can be automated.
  • EXISTS Proven quantitative finance libraries and models — valuation and risk maths is well established and cheap to run deterministically.
  • PARTIAL Large language models with retrieval and tool use — they write fluently but are unreliable at arithmetic and prone to confident fabrication without grounding.
  • PARTIAL Evaluation and audit tooling for AI output — financial text needs traceable provenance, and systematic scoring of generated analysis is still maturing.
  • EXISTS Regulatory and internal control framework for automated research — research and personalised advice are regulated activities, so liability and review requirements shape what can be automated.
12Path to Full Scale
  1. Now: automated earnings summaries, screening and monitoring dashboards with an analyst in the loop — large time savings on repetitive data gathering and first-pass screening.
  2. Next: agentic pipelines producing cited, auditable first-draft memos end to end — analysts shift from writing to reviewing and challenging.
  3. Next: continuous monitoring that flags thesis-breaking changes in real time — coverage of far more companies than a human team could track.
  4. Longer term: autonomous analysis for narrow, well-specified mandates under human supervision — cheap, always-on analysis — bounded by model reliability, audit and regulatory limits rather than by computing power.
