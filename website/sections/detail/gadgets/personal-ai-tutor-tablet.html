9Engineering Breakdown
  • Compute module — runs the tutor locally so it works without a network and keeps student data on the device. Key parts: system-on-chip with a neural processing unit (NPU), 8–16 GB of low-power memory, shared memory bus between CPU, GPU and NPU.
  • Model runtime — executes a compressed language model fast enough for spoken conversation. Key parts: quantised model weights (typically 4-bit), inference engine with NPU kernels, key-value cache manager, thermal and power governor.
  • Curriculum and knowledge layer — grounds every answer in the syllabus rather than the model's general memory. Key parts: curriculum knowledge graph mapped to standards, vector index of chunked lesson content, retrieval-augmented generation pipeline, source citations.
  • Learner model — tracks what the student actually knows and decides what to ask next. Key parts: knowledge-tracing estimator per skill, spaced-repetition scheduler, difficulty calibrator, mastery record stored on device.
  • Tutor dialogue layer — turns the learner model into Socratic conversation instead of answer-giving. Key parts: agent loop with tool calls, pedagogy-tuned prompt and policy, age-appropriate safety filters, speech recognition and synthesis.
  • Input and work surface — lets the device see handwritten and spoken work. Key parts: stylus digitiser, handwriting and maths-notation recognition, microphone array, camera for paper worksheets.
10How It Would Be Made — Step by Step
  1. Map the curriculum. Subjects are broken into a graph of fine-grained skills, each with prerequisites, mapped to published standards so progress transfers between schools.
  2. Curate and index content. Licensed lessons, worked examples and question banks are chunked, embedded and stored in an on-device vector index, with each item tagged to its skill node.
  3. Train the tutor behaviour. A base language model is fine-tuned on tutoring transcripts so that it asks leading questions, diagnoses errors and withholds final answers until the student gets there.
  4. Compress the model. Weights are quantised, pruned and distilled until the model fits the tablet's memory budget and runs at conversational latency, with quality measured against the uncompressed version.
  5. Optimise for the NPU. Operators are rewritten for the chip's accelerators, memory traffic is reduced, and the runtime throttles gracefully rather than overheating the fanless case.
  6. Build the learner model. Each answer updates a per-skill mastery estimate; a scheduler brings back weak skills at expanding intervals instead of repeating what is already known.
  7. Wire the agent loop. Retrieval, mastery estimation, question selection and dialogue are joined into one loop that can plan a session, react to confusion and stop when the student is tired.
  8. Harden privacy and safety. Speech and handwriting are processed on device, cloud calls are opt-in, and filters block age-inappropriate content; the design targets child-data rules such as COPPA, FERPA and GDPR.
  9. Validate learning gains. Randomised classroom trials compare progress against ordinary homework and against a teacher-only control, and the curriculum graph is corrected where the model misleads.
11Prerequisite Technologies
  • EXISTS Small language models that fit in a tablet — models in the low billions of parameters now give useful reasoning at 4-bit precision.
  • PARTIAL Edge NPUs with enough memory bandwidth — accelerators make inference fast, but bandwidth and thermal limits cap model size in a fanless device.
  • EXISTS Quantisation and efficient inference — post-training quantisation and distillation cut memory roughly fourfold with modest quality loss.
  • PARTIAL Knowledge tracing and mastery estimation — long-studied statistically and now neural, but predictions are still noisy across subjects.
  • PARTIAL Curriculum-aligned, licensed digital content — retrieval is only as good as the mapped content behind it, and rights vary by country.
  • PARTIAL Evidence that AI tutoring improves learning — early trials show gains in narrow settings; results vary with subject, age and how the tool is used.
12Path to Full Scale
  1. Now: cloud-based AI tutors in pilot classrooms and consumer study apps, plus on-device assistants for narrow tasks such as vocabulary drill — large volumes of interaction data and the first controlled studies.
  2. Next: hybrid devices that run a small tutor locally and call the cloud only for hard questions — offline use, low latency and stronger student privacy.
  3. Next: a persistent learner model that follows a student across subjects and years with teacher-visible reporting — genuinely continuous personalisation rather than per-session chat.
  4. Longer term: multimodal tutoring that reads handwritten working, spots the exact step where reasoning fails, and links to formal assessment — credible replacement for one-to-one human tutoring in well-structured subjects.
