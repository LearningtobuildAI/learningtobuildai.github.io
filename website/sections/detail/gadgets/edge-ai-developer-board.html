PART 3Engineering & Build Guide

Written by DeepSeek (deepseek-flash) on 29 Sep 2026. General engineering knowledge, not a manufacturer's procedure.

9Engineering Breakdown
  • Compute engine — runs the neural network's tensor operations. Key parts: system-on-chip with CPU cores, GPU or NPU for matrix multiplication, digital signal processors, memory controller.
  • Memory — holds model weights and the key-value cache during inference. Key parts: LPDDR5 or LPDDR5X packages, high-bandwidth memory stacks (on higher-end boards), on-package or board-level routing.
  • Power and thermal — supplies stable voltage and removes heat within a small enclosure. Key parts: multi-phase voltage regulators, heat spreader and heatsink, fan or fanless thermal solution, thermal interface materials.
  • Storage and I/O — loads models quickly and connects to sensors, networks and displays. Key parts: NVMe flash or eMMC, PCIe lanes, USB, Ethernet, Wi-Fi, camera and display interfaces.
  • Software stack — lets developers compile, quantize and run models on the hardware. Key parts: drivers and firmware, inference runtime and graph compiler, quantization and pruning tools, model zoo and examples.
10How It's Made — Step by Step
  1. Define the target. Set the maximum model size (in billions of parameters), token throughput, power budget (often 10–60 W) and required ports.
  2. Select or design the SoC. Choose a chip with an NPU or GPU that accelerates matrix math, or design one with enough on-chip memory to avoid bottlenecks.
  3. Integrate memory. Solder LPDDR5 packages close to the SoC for high bandwidth, or use on-package high-bandwidth memory where the design allows.
  4. Fabricate the PCB. Lay out high-speed differential pairs for memory and PCIe, manage power planes and impedance, then manufacture the multi-layer board.
  5. Assemble the board. Pick-and-place the SoC, memory, power stages and connectors, reflow-solder them, and underfill the largest chips for reliability.
  6. Test and bin. Run functional tests, measure memory bandwidth and thermal performance under sustained load, and sort boards by stable clock speed.
  7. Write firmware and drivers. Bring up the bootloader, power management and accelerator drivers so the operating system can use the NPU and memory correctly.
  8. Build the software stack. Port an inference runtime, add quantization support (e.g., 4-bit and 8-bit), and provide tools to convert popular model formats.
  9. Validate real workloads. Run representative language models, measure tokens per second and power draw, and tune scheduling so the board stays within its thermal limit.
11Prerequisite Technologies
  • EXISTS NPUs or GPUs with matrix-multiply acceleration — general-purpose CPUs are far too slow for real-time language model inference.
  • PARTIAL High-capacity, high-bandwidth memory — holding billions of parameters needs tens of gigabytes and hundreds of gigabytes per second; LPDDR5 is affordable but HBM remains costly and power-hungry.
  • EXISTS Model quantization and compression — reducing weights to 4 or 8 bits shrinks models enough to fit in edge memory with modest quality loss.
  • EXISTS Efficient inference runtimes and compilers — they map model graphs onto the available accelerators and manage the key-value cache to avoid recomputation.
  • EXISTS Compact power delivery and cooling — sustained inference produces heat that must be removed from a small, often fanless enclosure.
12Where It Goes Next
  1. Now: developer boards with 8–32 GB of memory run quantized 7–13 billion parameter models at a few tokens per second — local chatbots, document search and private inference without cloud calls.
  2. Next: unified memory of 64–128 GB on a single board — running 70 billion parameter models locally for more capable assistants and coding tools.
  3. Next: chiplet designs with on-package high-bandwidth memory exceeding 1 TB/s — faster token generation and support for larger context windows.
  4. Longer term: on-device fine-tuning and multimodal models — personalized AI that adapts to a user's data without sending it to a data centre.
