9Engineering Breakdown
  • Compute array — does the multiply-accumulate arithmetic at high parallelism. Key parts: multiply-accumulate (MAC) units, systolic or SIMD data path, accumulators.
  • On-chip memory — feeds weights and activations to the array fast enough to keep it busy. Key parts: weight buffers, activation buffers, SRAM banks, register files.
  • Data-movement fabric — moves tensors between memory, array and the rest of the chip. Key parts: DMA engines, on-chip interconnect, interface to shared SoC memory.
  • Controller and scheduler — sequences operations, tiles tensors and overlaps memory with compute. Key parts: instruction sequencer, pipeline control, tiling logic.
  • Numeric conversion — translates between full-precision models and the low-precision formats the array uses. Key parts: quantisation and scaling units, zero-point handling, rounding and clipping.
  • Host and power interface — lets the CPU or GPU hand work to the NPU and gates unused blocks. Key parts: CPU/GPU handshake, clock and power gating, thermal sensors.
10How It's Made — Step by Step
  1. Define the workload and number formats. Engineers choose INT8, FP16 or mixed precision, a throughput target in TOPS and a power budget set by the device's battery and cooling.
  2. Design the architecture. They decide the array size, dataflow, memory hierarchy and how much SRAM fits in the area budget.
  3. Write and verify the RTL. The design is described in hardware description language, then simulated, formally checked and run on emulators against real neural networks.
  4. Do physical design. Synthesis, floorplanning, place-and-route and timing closure turn the logic into a manufacturable layout, with careful clock and power distribution.
  5. Integrate into the system-on-chip. The NPU block is connected to CPU, GPU, memory and peripherals through the chip's interconnect, and its caches and power domains are tied in.
  6. Fabricate the silicon. A mask set is made and wafers are processed at an advanced logic node; each die is tested before packaging.
  7. Package and validate. The SoC is packaged, and system-level tests check thermal behaviour, power and real inference workloads.
  8. Build the software stack. A graph compiler, kernel library and runtime map models from frameworks onto the NPU, inserting quantisation and fallback paths.
  9. Tune on device. Operators that do not fit are optimised or offloaded, and power and thermal limits are tuned for sustained rather than peak performance.
11Prerequisite Technologies
  • EXISTS Advanced logic process nodes — dense, low-power transistors are needed to put a useful array on a phone chip.
  • EXISTS Low-power SRAM — weights and activations must sit close to the arithmetic to avoid burning energy on data movement.
  • EXISTS Quantisation-aware training — models must tolerate INT8 or lower precision without losing useful accuracy.
  • EXISTS Neural-network compilers and runtimes — without them, developers cannot easily get models onto the specialised hardware.
  • EXISTS High-bandwidth memory interfaces — larger models still need to stream data from shared memory without stalling the array.
12Where It Goes Next
  1. Now: NPUs in smartphones, tablets and laptops handling camera, speech and photo tasks — private, low-latency inference without a network round trip.
  2. Next: on-device large language models running with unified memory and mixed precision — assistants that work offline and keep data on the device.
  3. Next: chiplets and heterogeneous compute that share memory between CPU, GPU and NPU — larger models and more flexible scheduling on battery-powered devices.
  4. Longer term: in-memory and analog compute blocks for matrix multiplication — much better energy efficiency, if accuracy and manufacturing variability can be controlled.
