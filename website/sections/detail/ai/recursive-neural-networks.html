4How It Works

RNNs process input sequences by breaking them down into smaller, more manageable parts and then reassembling the output. They maintain a memory state that captures information from previous steps, allowing them to handle complex relationships within data structures.

9Engineering Breakdown
  • Tree input representation — recursive nets need a hierarchy, not a flat sequence, so each input is first cast as a tree. Key parts: constituency or dependency parse, leaf tokens, per-node labels where available.
  • Leaf encoder — turns the smallest units into vectors the composition function can combine. Key parts: pre-trained word or symbol embeddings, sub-token features where words are rare.
  • Composition cell — the core operator: merges two child vectors into a parent vector, and is reused at every node. Key parts: weight matrix (or tensor for multiplicative interaction), bias, nonlinearity such as tanh.
  • Gating and stability layer — controls how much each child contributes so gradients survive deep trees. Key parts: forget/input gates (as in a tree-structured LSTM), layer normalisation, dropout.
  • Training machinery — learns shared parameters by walking the tree in both directions. Key parts: loss over node or root labels, backpropagation through structure, optimiser with gradient clipping.
  • Readout — turns node vectors into answers — a class, a score or a generated structure. Key parts: root-level classifier or regressor, optional per-node tagging head.
10How It Would Be Made — Step by Step
  1. Parse the data into trees. Run a statistical or neural parser over text (or a compiler front end over code) to produce a binary or n-ary tree for every example.
  2. Vectorise the leaves. Replace each token with a pre-trained embedding; keep the tree topology in a stack or adjacency record so the recursion knows which pairs combine.
  3. Define the composition function. Choose an operator such as a shared weight matrix applied to the concatenated children, or a higher-order tensor if multiplicative interactions between children matter.
  4. Forward recursion. Walk the tree bottom-up: compose every sibling pair, then their parent, until the root holds one vector for the whole structure.
  5. Backward pass through structure. Run reverse-mode differentiation over the tree, accumulating gradients into the single shared parameter set at every node.
  6. Add supervision at every node. Label intermediate phrases, not just the root, so shallow nodes receive gradient and the shared weights learn useful compositions.
  7. Stabilise for depth. Introduce gates, normalisation and gradient clipping; test on trees deeper than those seen in training to expose vanishing gradients.
  8. Evaluate and deploy. Measure accuracy against sequence-based baselines, then batch and prune the tree computation for inference cost.
11Prerequisite Technologies
  • EXISTS Accurate automatic parsers — the architecture has no way to learn a hierarchy from raw text in its classic form — the tree must be supplied.
  • EXISTS Pre-trained distributed word embeddings — leaves need meaningful vectors before composition can build phrase meaning.
  • EXISTS Automatic differentiation over graph structures — gradients must flow through a variable-shape recursion, not a fixed sequence of layers.
  • PARTIAL Tree-annotated labelled datasets — phrase-level sentiment treebanks exist for English, but equivalents for most languages, code and scientific text are scarce.
  • EXISTS GPU training and inference stacks — many small irregular operations per example make naive implementations slow without batched tree kernels.
12Path to Full Scale
  1. Now: sequence and attention models dominate text, while recursive cells survive in niche structured tasks — a cheap inductive bias for source-code ASTs, chemical structures and formula parsing.
  2. Next: hybrids that bolt an explicit recursion onto a pre-trained transformer backbone — better systematic generalisation — handling novel combinations of known parts.
  3. Next: standard benchmarks for compositional generalisation with tree-shaped supervision — evidence on exactly when hierarchy beats raw sequence order.
  4. Longer term: recursive modules inside program-synthesis and planning systems — models that produce and verify nested structures, such as code or proofs, natively.
