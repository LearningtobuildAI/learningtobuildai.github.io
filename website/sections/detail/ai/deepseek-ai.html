9Engineering Breakdown
  • Tokenizer and embeddings — turns raw text into the integer tokens the network actually processes. Key parts: byte-level tokenizer, large vocabulary lookup, embedding matrix.
  • Attention layers — let every token weigh every other token in the context. Key parts: multi-head latent attention with a compressed key-value cache, rotary position encoding.
  • Mixture-of-experts feedforward layers — provide most of the model's stored knowledge while only activating a slice per token. Key parts: bank of expert subnetworks, router that picks a few experts per token, load-balancing scheme.
  • Training stack — runs the pretraining job across thousands of accelerators. Key parts: distributed training framework, 8-bit floating point kernels, data pipeline, checkpointing and failure recovery.
  • Post-training and reasoning — turns a text predictor into something that reasons and follows instructions. Key parts: supervised fine-tuning data, reinforcement learning with rule-checkable rewards, reward models and verifiers, distillation into smaller models.
  • Inference and serving — delivers the model cheaply enough to be used at scale. Key parts: quantised weights, key-value cache management, batching and scheduling, API and chat front end.
10How It's Made — Step by Step
  1. Assemble the training corpus. Crawl and licence text and code, then filter, deduplicate and quality-score it — the published pretraining run consumed on the order of 15 trillion tokens.
  2. Train the tokenizer. Fit a byte-level vocabulary of roughly 128,000 tokens so common words and code fragments become single units.
  3. Pretrain the base model. Predict the next token over the corpus on a large cluster of accelerators, training in 8-bit floating point and routing each token to a few experts out of many, in a model with about 671 billion parameters of which roughly 37 billion are active per token.
  4. Supervised fine-tuning. Train on curated instruction-and-answer pairs so the model responds usefully rather than just continuing text.
  5. Reinforcement learning for reasoning. Generate many candidate solutions to maths, code and logic problems, automatically check which answers are correct, and reinforce the paths that got there — letting a reasoning mode emerge without human-written chain-of-thought examples.
  6. Distil smaller models. Use the large model's outputs to train compact dense models that run on modest hardware.
  7. Evaluate and red-team. Benchmark reasoning, coding and multilingual ability, and probe for harmful or unsafe outputs.
  8. Serve and iterate. Quantise the weights, run them behind an API or release them openly, and collect feedback for the next training round.
11Prerequisite Technologies
  • EXISTS High-performance GPU accelerators and fast interconnect — pretraining is limited by how many chips can be kept busy at once; export controls have shaped which chips are available.
  • EXISTS Large-scale distributed training software — a single model cannot fit on one device, so parallelism and fault recovery are essential.
  • EXISTS Web-scale, well-filtered text and code corpora — capability scales with the quality and diversity of the pretraining data.
  • EXISTS Low-precision (8-bit) training — halves memory and speeds up arithmetic relative to 16-bit training.
  • PARTIAL Automatically verifiable rewards — reinforcement learning works well where answers can be checked by a program or formula, and poorly where quality is subjective.
12Where It Goes Next
  1. Now: open-weight mixture-of-experts chat and reasoning models released under permissive licences — strong reasoning available to any organisation that can host or call the model.
  2. Next: longer context, cheaper inference and more reliable tool use — agents that work through multi-step tasks rather than answering single questions.
  3. Next: small distilled models running on phones and laptops — private, low-latency assistants that need no data centre.
  4. Longer term: domain adapters for finance, healthcare and logistics with audit and verification built in — use in regulated work — only where accuracy, provenance and accountability can be demonstrated.
