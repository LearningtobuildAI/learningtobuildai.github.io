9Engineering Breakdown
  • The model under study — the opaque machine-learning system whose behaviour must be explained. Key parts: trained neural network or ensemble, inference interface exposing outputs, and where possible gradients and internal activations.
  • Attribution methods — estimate how much each input feature contributed to a given output. Key parts: perturbation and sampling estimators, gradient and path-integral methods, surrogate models fitted locally around one prediction.
  • Concept and representation probes — look inside the network rather than only at its inputs and outputs. Key parts: probe classifiers trained on hidden activations, sparse dictionaries of interpretable directions, circuit analysis tracing which components drive a behaviour.
  • Example-based explanations — explain a decision by comparison with real or synthetic cases. Key parts: influence functions tracing training examples, counterfactual and contrastive generators.
  • Faithfulness evaluation — tests whether an explanation actually reflects the model, not just looks plausible. Key parts: deletion and insertion tests, randomisation and sanity checks, agreement across independent methods.
  • Human interface and governance — turns scores into something a person can act on and audit. Key parts: visualisation and summary dashboards, model cards and data documentation, logging for downstream review.
10How It's Made — Step by Step
  1. Define the question. Decide exactly what must be explained — one prediction, overall model behaviour, a subgroup, or a suspected failure mode — because the answer determines which method is valid.
  2. Instrument the model. Expose outputs, gradients and selected internal activations through an inference wrapper so explanation code can query the model repeatedly without retraining it.
  3. Pick a method class. Choose attribution, probe-based or example-based approaches according to whether inputs, internals or training data are accessible, and how much compute is acceptable.
  4. Generate explanations. Run the chosen estimator over the model — often thousands of forward passes per explanation — and aggregate the results into per-feature, per-concept or per-example scores.
  5. Validate faithfulness. Test explanations against the model itself: remove the features they mark as important and check the output actually moves, and confirm that randomising the model changes the explanation.
  6. Check human usefulness. Have domain experts use the explanations on real decisions and measure whether they detect errors or change their judgement appropriately.
  7. Deploy and monitor. Serve explanations alongside predictions, document the method's known limits, and re-run validation whenever the model or its data distribution changes.
11Prerequisite Technologies
  • EXISTS Trained models with queryable internals — explanation methods need repeated access to outputs, gradients or activations.
  • EXISTS Attribution and probing algorithms — methods such as additive feature-attribution estimators and activation probes are mature and widely implemented.
  • PARTIAL Ground-truth or causally valid test data — faithfulness is easy to measure on synthetic tasks and much harder on real-world models.
  • PARTIAL Benchmarks for explanation quality — there is no settled standard for comparing explanations across models and tasks.
  • EXISTS Compute for repeated inference — many methods require thousands of extra forward passes per explanation.
12Where It Goes Next
  1. Now: post-hoc attribution and documentation routinely shipped with models — debugging, regulatory reporting and basic user trust.
  2. Next: concept-based and circuit-level interpretability on frontier models — explanations that describe internal features rather than only input importance.
  3. Next: standardised faithfulness benchmarks and third-party audits — comparable, testable claims about model transparency.
  4. Longer term: interpretability that reliably predicts behaviour before deployment — safety cases that rest on understanding a model, not only on testing it.
